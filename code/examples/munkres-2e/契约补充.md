## 2. 本书的结构

```
内容库        MunkresLean/           （只有 Base.lean 可 import Mathlib，其余只 import Base + 本库）
聚合文件      MunkresLean.lean       （生成物 cli sync-root 产出，不要手改）
清单 / 入序表 knowledge/pipeline/    （sectionNN.json 单一事实源；入序表管跨节写序）
基底          MunkresLean/Base.lean + knowledge/pipeline/基底.json
术语表        knowledge/glossary.json（长程记忆：术语 → 章节 / 原子 / Lean / 清单指针）
书配置        knowledge/books/munkres-2e.json（页码提取参数；换书改它 + book-build）
页码索引      knowledge/books/munkres-2e/index.json（生成物；所有页码查询只读索引）
```

**本书章节特例**：英文原书第 13、14 章在**装订顺序上对换**（14 章页排在 13 章之前）。
一切「顺序」按**物理页序**，节号/章号只是标签，不要求单调；禁止假设「编号递增 ⟹ 页码递增」。
md 转录的 `p####.md` 中 `####` = **英文 PDF 页号**（不是印刷页）。

**书在库外**：英文 PDF / md 转录 / 中译本目录索引都不在仓库里，路径见 profile 的 `env`
（`KL_BOOK_PDF` / `KL_BOOK_MD` / `KL_BOOK_INDEX`）。换机器只改 profile 与书配置，不改代码。

## 3. 命令（只写差异；完整前缀见 `docs/资源与数据源.md` §3.1）

```
python -m kl.cli <sections|doctor|config|stats|next|status|book|book-build|book-locate|init|check|
                  audit|link|figure|graph|sync-root|probes|fix-headers|new-module|quote-check|glossary>
```

- 门禁：`pipeline_gate(n)` 与 `pipeline_doctor()`（本插件工具，直接走 CLI，绕开 MCP 工具表陈旧问题）

  术语表 / 页码索引）；不要猜环境变量，也不要手写绝对路径

## 4. 本书特有的纪律

- **基底变更规程**：见 `docs/管线.md`「基底变更规程」——Base.lean 与 `基底.json` 必须同改，
  跑已 verified 节的全量回归，Lead 复核后才算；worker 不要单独动基底。
- **图数据**：每节收口后由 Lead 重生成（`kl graph --export knowledge/pipeline/graph.json`
  → `tools/kl/viz.py` 重渲染）；worker 不写 `graph.json` / `graph.svg` / `graph.html`。
- **页码**：`kl_book(n)` / `kl_book_locate` 读索引；人工翻书只用于抽查，
  报告里引用页码一律写「印刷页 p.XXX（英文 2e）」并注明中译本范围。
- **本节完成的定义**：`pipeline_gate(n)` ok（含 ③b 判重）+ `pipeline_doctor` 全绿；
  入序表标 `done:SectionN` 由 Lead 改，worker 不改入序表。

## 5. 工作基准（本工程的初始决策，来自旧 `dsh-munkres-prompt` 插件）

以**原书**的编排为准：

- 书里每一句都是一个独立节点（特例也保留）；
- B 层边（证明里的提及）留在书的子图内 —— 证明按书的思路走，不引用库的一般版；
- A 层边（陈述里的提及）必然指向 mathlib（书没有自己的类型系统）；
- 代价：会重证一些库里有一般版的定理。这**不是错误**，是基准的选择；
- 基准可切换（book / mathlib），但切换后所有派生量（级次 / 束 / 视图）必须**重新计算**。
