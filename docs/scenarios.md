# 应用场景

主线是数学教材。但方案的本体是「**有严格陈述的文本 → 原子 → 可检查形式化 → 图**」，
任何满足这个结构的材料都可以套用。按"形式化代价从低到高"排：

## 1. 数学教材 / 讲义 / 习题课（主线）

- 最匹配：定义—定理—证明结构清晰，数学库（mathlib）覆盖好。
- 产出价值：教材配套的可检查形式化库、知识点图、习题到知识点的映射。
- 本方案实例即此类（Munkres《Topology》）。

## 2. 计算机科学理论教材

类型论、形式语言、算法正确性、密码学原型、程序语义、逻辑教材——
这些内容本身就是"定义 + 定理 + 构造"，和 Lean/Coq/Isabelle 的表述方式几乎同构，
转录到形式化的损耗比拓扑教材更小。

## 3. 形式化论文 / 学术讲义

很多论文有"定理—引理—证明"骨架，且作者愿意/需要机器检查。
这套管线可以：
- 把论文拆成原子（写作前先把论文变成清单，本身就是一种大纲工具）；
- 为每个定理找已有的形式化库对应（判重与复用）；
- 生成论文的"引用完整性图"（谁依赖谁，哪些引理没证）。

## 4. 标准 / 协议 / 规范文本（RFC、语言规范、接口规范）

可行但需要裁剪：这类文本不是"定理"，而是"规则 + 一致性要求"。
适用子集：形式语义、状态机、类型规则、一致性条件。
产出：可检查的形式模型 + 条款到模型的对照图（条款 = 原子，模型 = 声明）。
不适合把整份规范都原子化——叙述性条款形式化收益低。

## 5. 法规 / 政策 / 合同（弱形式化）

真正的形式化代价高，但可以退一步：条款原子化 + 术语表 + 交叉引用图 +
可检查的"条款一致性"检查（例如同一术语的定义是否冲突）。
价值在审计与检索，而非证明。

## 6. 领域知识图谱构建

不追求形式化时，前两层（转录 + 原子）已经能产出高质量的领域知识库：
教材 → 原子（定义/定理/例子）→ 术语表 + 依赖图。可用于检索、问答、
课程设计、知识追踪（学生学到哪、卡在哪）。

## 7. 教学与自测

原子图天然是"知识点图"。可以在此之上生成：
- 每个原子的前置依赖（拓扑序 → 学习路径）；
- 习题 ↔ 原子的映射（哪道题考哪些定理）；
- "证明批改"：学生的证明步骤是否落在正确的原子上。

## 8. 已有形式化库的"回挂原文"

反向使用：已经有一个 Lean/Coq 库时，可以把它回挂到一本教材的原文上，
生成"教材 ↔ 库"的对照图，用于教学或维护（哪些声明没有原文出处、哪些定义有分歧）。

## 9. 多版本 / 多语言教材对齐

同一本书的不同版次/译本 → 各自原子化 → 对齐同一批原子（版本 diff、翻译一致性、
公式符号差异）。对做教材维护或双语教学的人有用。

## 不适合的场景（边界）

- 纯叙述性文本（小说、散文、新闻）：没有"可独立判断真假"的单位；
- 没有稳定页码/版式的材料：页码索引这一层就断了；
- 形式化收益极低的领域：完整形式化的成本 >> 收益时，最多只做前两层；
- 版权受限且无法合法使用的材料：方案要求引用原文，绕不开版权问题。

---

**一句话总结**：只要一份材料能被切成"可引用、可判断真假"的原子，并且这些原子
值得被机器检查（哪怕只是检查一致性而不是证明），这套管线的前两层就适用；
后两层（Lean 形式化、图断言）则取决于领域与库的适配度。
